# [TC-10-16] A description of 600 characters is taken whole by the box and only its first 500 reach the model

|  |  |
| --- | --- |
| **Layer** | desktop |
| **Verifies** | `US-10-02#6` |
| **Role** | User |
| **Type** | edge |
| **Automation** | auto |
| **Depends on** | — |

## Preconditions

- Empty config, cache and data directories.
- No Google account: the app was started with "Use without an account"; the local calendar "My calendar" is the default calendar.
- Events from a description on, with the default address `http://localhost:11434` and model `gemma4:e4b`; a fake Ollama at that address that has the model, records every request it receives and answers each description with the fixed answer given in Test data.
- A fixed clock: Monday 2026-10-26 09:00, Europe/Warsaw.

## Test data

| What | Value / source |
| --- | --- |
| Description | 600 characters: "Kino jutro o 20. " followed by "żółć " repeated, ending with "KONIEC" in the last 100 characters |
| Fake model's answer | add · title "Kino" · tomorrow · 20:00 |

## Steps

| # | Action | Expected result | Evidence |
| - | ------ | --------------- | -------- |
| 1 | Press `q` and paste the description. | The box holds all 600 characters, "KONIEC" included. | app state |
| 2 | Press Enter; read the fake Ollama's record. | The description it received is exactly the first 500 characters (letters, not bytes) and has no "KONIEC"; the window opens. | fake Ollama record |

## Pass criterion

- The box never refuses a long description, and the model never receives more than its first 500 characters.

## Cleanup

- The fakes and the config, cache and data directories are discarded with the test.

## Out of scope for this test

- What the model makes of a long description.
- The fake model's answers are fixed, so this test proves what the app does with an answer, not what a real model understands — that is `TC-10-19`.
